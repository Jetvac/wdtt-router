# WDTT Router

Панель для цепочки VPN-серверов, связанных через **Cloudflare Mesh**. Первый сервер (вход) держит панель и клиентские сервисы — **WDTT** и/или **3x-ui**, — остальные серверы передают трафик дальше по цепочке и выпускают его в Интернет с последнего (выход).

```text
Клиенты WDTT / 3x-ui
   │
   ▼
[вход + панель] ──Mesh──▶ [промежуточный] ──Mesh──▶ … ──Mesh──▶ [выход] ──▶ Интернет
```

## Чем это отличается от прежней версии

- **Серверы не знают друг о друге.** Узлы общаются только через частные адреса Cloudflare Mesh (100.96.0.0/12). Каждый сервер знает лишь Mesh-адрес следующего звена; выход видит только Mesh-адрес предыдущего и не знает ни публичных адресов цепочки, ни сервера панели.
- **Луковичное шифрование.** Вход шифрует поток отдельно для каждого звена (VLESS Encryption: ML-KEM-768 + X25519, вид «случайных байтов»). Промежуточные серверы и сам Cloudflare видят только шифротекст; расшифровать трафик клиента может только выходной сервер.
- **Закрыты все порты.** На каждом сервере nftables с политикой drop. Звено цепочки и SSH принимают подключения только из Mesh; публичный SSH промежуточных и выходных серверов закрыт — панель управляет ими через Mesh. Наружу на входе открыты только порт панели, UDP-порт WDTT и порты включённых подключений 3x-ui (синхронизируются автоматически).
- **Без утечек.** Трафик клиентов WDTT и 3x-ui уходит только в цепочку. Если цепочка недоступна, у клиентов пропадает Интернет — трафик никогда не выходит напрямую с адреса входного сервера (kill switch на уровне ядра).
- **WDTT и 3x-ui независимы.** Каждый включается и выключается отдельно, в любой комбинации, сколько угодно раз.
- **Устойчивость.** Панель хранит желаемое состояние каждого сервера, а агент приводит сервер к нему идемпотентно. Все изменения выполняются одной очередью; повторные нажатия объединяются. Изменения firewall применяются с таймером отката: если панель после изменения не смогла подключиться заново, через 2 минуты правила возвращаются сами. Состояние переживает перезагрузку, а сброс правил маршрутизации (например, `netplan apply`) исправляется автоматически.
- **Собственный сервер WDTT.** Совместим со стандартными клиентами (тот же протокол и ссылка `wdtt://`), но быстрее и устойчивее исходного: WireGuard без промежуточного UDP-сокета, переподключение клиентов за секунды после перезапуска, ключи доступа с привязкой к устройству, сроком и статистикой, смена паролей без разрыва соединений. Подробнее — [docs/wdtt.md](docs/wdtt.md).
- **Приложение вместо скрипта.** Один бинарный файл Go: панель, агент и сервер WDTT. Интерфейс на React + Ant Design.

## Требования

- Debian 12/13 или Ubuntu 22.04/24.04, systemd, root; amd64 или arm64. Рекомендуется не меньше 1 ГБ ОЗУ.
- Отдельный аккаунт **Cloudflare Zero Trust** и API-токен с правами **Cloudflare One Connectors Write** и **Zero Trust Write**.
- В панели Cloudflare однажды включите *Allow all Cloudflare One traffic to reach enrolled devices* (через API этот параметр не меняется; панель проверит связь между узлами фактически).

## Установка

На сервер, который станет входом и будет держать панель:

```bash
curl -fsSLO https://github.com/Jetvac/wdtt-router/releases/latest/download/install.sh
sudo bash install.sh install --public-host ВАШ_IP
```

Установщик проверяет SHA-256 архива, ставит службу `wdtt-router` и **один раз** выводит логин, пароль и отпечаток сертификата. Откройте `https://ВАШ_IP:8443/` и сверьте отпечаток (`sudo wdtt-router fingerprint`).

## Первый запуск

1. **Cloudflare Mesh** — введите Account ID, команду и токен. Панель проверит аккаунт и предложит исправить найденное: включить нужные настройки устройств, создать профиль Mesh или отключить профиль «full tunnel», если он перехватывает весь трафик узлов.
2. **Серверы** — подключите сервер панели к Mesh, затем добавьте остальные серверы по IP и паролю root. Пароль используется один раз, чтобы добавить ключ панели; он не сохраняется. Новый сервер сразу подключается к Mesh, а его публичный SSH закрывается.
3. **Цепочка** — расставьте серверы по порядку и нажмите «Сохранить и применить». Панель настроит звенья от выхода к входу и проверит TCP и UDP через всю цепочку.
4. **Сервисы** — включите WDTT и/или 3x-ui. Для WDTT выдайте каждому устройству свой ключ доступа: панель покажет ссылку `wdtt://` и QR-код для стандартного клиента. Доступ к 3x-ui открывается через SSH-туннель. Просмотр паролей фиксируется в журнале.

## Обслуживание

```bash
sudo bash install.sh update            # обновить; при ошибке запуска возвращается прежняя версия
sudo bash install.sh rollback          # вернуть версию до последнего обновления
sudo bash install.sh uninstall         # удалить панель, сохранив данные
sudo wdtt-router reset-password        # новый пароль администратора
sudo wdtt-router agent status          # состояние компонентов этого сервера (JSON)
sudo wdtt-router agent probe           # проверка цепочки с входного сервера
```

Агенты на остальных серверах обновляются автоматически при следующем применении настроек.

## Разработка

```bash
cd web && npm ci && npm run build && cd ..        # интерфейс (встраивается в бинарный файл)
go test ./... && go vet ./...
CGO_ENABLED=0 GOOS=linux go build -o wdtt-router ./cmd/wdtt-router
cd web && npm run dev:mock                         # интерфейс с тестовыми данными, без серверов
```

Тег `vX.Y.Z` собирает архивы для amd64/arm64 и `SHA256SUMS` в GitHub Release.
