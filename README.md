# WDTT Mesh Control Panel

Панель для двух и более Linux VPS: WDTT принимает трафик клиента на входном сервере, а Cloudflare Mesh доставляет его на выходной сервер. При необходимости панель добавляет приватный VLESS вход 3x-ui и направляет через него трафик WDTT. Интерфейс и API работают по HTTPS; операции с сетью имеют независимый таймер отката.

> Проект работает с реальными маршрутами и firewall. Перед применением убедитесь, что есть консоль провайдера VPS и отдельный тестовый Cloudflare Zero Trust аккаунт. Панель не должна управлять существующими Mesh ресурсами другого проекта.

## Требования

- Debian или Ubuntu, systemd, IPv4, root SSH на управляемых VPS;
- два VPS для входного и выходного узлов, доступ в Интернет и UDP для WDTT и Cloudflare Mesh;
- Cloudflare Zero Trust аккаунт с разрешением создать отдельный профиль, два Mesh узла и маршруты;
- Docker для Mesh (панель может установить его на узел);
- для прозрачного VLESS клиента сейчас требуется Linux amd64; панель и Mesh поддерживают amd64/arm64.

Программа собирается Go 1.22 с CGO для SQLite. Поддерживаемые сценарии проверены на двух временных VPS. Проверка настоящего клиента PWDTT зависит от наличия такого клиента.

## Установка

После публикации релиза скачайте `install.sh` из [последнего релиза](https://github.com/Jetvac/wdtt-router/releases/latest), проверьте его содержимое и запустите на входном VPS:

```bash
sudo bash install.sh install --public-host YOUR_PUBLIC_IP --port 8443
```

Установщик загружает архив для своей архитектуры и `SHA256SUMS`, проверяет SHA-256, создаёт службу `wdtt-panel.service` и выводит первый логин и пароль **один раз**. Сохраните пароль в менеджере паролей. Откройте `https://YOUR_PUBLIC_IP:8443/`; сертификат при первой установке самоподписан. Сверьте его отпечаток по консоли VPS, прежде чем принимать исключение браузера:

```bash
openssl x509 -in /var/lib/wdtt-panel/panel.crt -noout -fingerprint -sha256
```

Панель запускается от root, поскольку управляет маршрутизацией, firewall, Docker и systemd. Доступ к порту 8443 ограничьте доверенной сетью на уровне провайдера или внешнего firewall. Для учётной записи действует 12-часовая сессия и защита от CSRF.

## Первый запуск

1. На странице «Серверы» добавьте выходной VPS по root SSH. Панель проверит отпечаток SSH и установит тот же бинарный файл агента; дальнейшие подключения используют отдельный ключ панели.
2. На странице «Cloudflare Mesh» сохраните Account ID, Team и API token **тестового** аккаунта. Выполните предварительную проверку маршрутов. Если она обнаружит пересечения, не создавайте ресурсы.
3. Создайте Mesh для входного и выходного узлов. Панель записывает ID и владельца каждого созданного ресурса, проверяет их состояние через Cloudflare API и не меняет чужие ресурсы.
4. На странице «WDTT» установите сервис на входном VPS. Укажите новый пароль, публичный адрес и действующую ссылку VK Call. Ссылку можно поменять через «Перенастроить».
5. На странице «Маршрутизация» примените выборочный маршрут для подсети WDTT. Маршрут сервера по умолчанию не переносится в Mesh.
6. При необходимости установите 3x-ui на обоих узлах. Её веб-панель и подписки слушают `127.0.0.1`; сохранённый доступ можно посмотреть после входа в WDTT-панель.
7. Для приватного VLESS включите вход на выходном сервере, скопируйте сохранённую ссылку, затем включите VLESS клиент на входном. Включение проверяет TCP и UDP до окончательного подтверждения.
8. Необязательно включите «Выход через WARP» на странице 3x-ui. Правило применяется только к приватному VLESS входу; панель проверит TCP и UDP и вернёт прямой выход при неудаче.
9. Правила ICMP и SSH настраиваются на странице «Firewall». Ограничение SSH вводите только с корректной подсетью управления.

Страница «Цепочки» хранит желаемый порядок узлов. Фактические маршруты для пары вход/выход задаются Mesh, маршрутизацией и VLESS; произвольная цепочка с промежуточными узлами пока не применяется автоматически.

Если WDTT уже установлен, выберите «Импортировать существующий WDTT». Панель проверит `wdtt.service` и запишет факт импорта без изменения его настроек. При наличии `/etc/wdtt-mesh-egress.conf` от v0.2.2 новая установка и перенастройка WDTT блокируются, чтобы не перезаписать старую схему. Управление службой остаётся доступным; переход к новой схеме требует отдельной миграции с сохранением прежней конфигурации.

## Безопасный доступ к 3x-ui

У 3x-ui нет публичного веб-порта. Узнайте порт и путь через кнопку «Показать сохранённый доступ» на странице 3x-ui, затем поднимите локальный SSH туннель с собственного компьютера:

```bash
ssh -L 127.0.0.1:LOCAL_PORT:127.0.0.1:PANEL_PORT root@VPS_IP
```

Откройте `http://127.0.0.1:LOCAL_PORT/WEB_BASE_PATH/` или `https://` согласно сохранённой схеме. Для выходного VPS SSH туннель подключается непосредственно к нему. Не публикуйте порт 3x-ui через reverse proxy без отдельной защиты.

## Проверка и восстановление

```bash
sudo wdtt-panel status
sudo wdtt-panel selftest
sudo wdtt-panel node probe-vless-client # только на входном узле с включённым VLESS
sudo wdtt-panel node probe-vless-client-json # показывает IP прозрачного TCP выхода и результат UDP
sudo systemctl status wdtt-panel wdtt cloudflare-mesh x-ui
```

В панели доступны «Операции», «Журнал» и диагностический JSON без сохранённых секретов. Приложение удаляет события, аудит и завершённые задания старше 24 часов. Подробности о проверках, таймере отката и ручном восстановлении: [docs/recovery.md](docs/recovery.md). Системный журнал `journald` регулируется настройками ОС отдельно.

## Обновление и удаление

```bash
sudo bash install.sh update --public-host YOUR_PUBLIC_IP --port 8443
sudo bash install.sh repair --public-host YOUR_PUBLIC_IP --port 8443
sudo bash install.sh uninstall
```

`update` останавливает службу, копирует SQLite и ключ шифрования, меняет бинарный файл атомарно и проверяет запуск. При ошибке возвращает прежний бинарный файл, базу и unit. Резервные копии находятся в `/var/lib/wdtt-panel/backups/`. `uninstall` удаляет только службу и бинарный файл панели; состояние сохраняется. `uninstall --purge` требует явного ввода `DELETE` и удаляет состояние панели, но не WDTT, Mesh и 3x-ui на узлах.

## Разработка и выпуск

```bash
go test ./...
go vet ./...
CGO_ENABLED=1 go build -o wdtt-panel ./cmd/wdtt-panel
bash -n install.sh
```

CI проверяет тесты, vet, форматирование и синтаксис установщика. Тег вида `vX.Y.Z` собирает Linux amd64/arm64 архивы и контрольные суммы в GitHub Release. Для локальной проверки установщика можно задать `WDTT_PANEL_ARTIFACT_DIR` с архивом и `SHA256SUMS`.
