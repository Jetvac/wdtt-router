# Безопасность

## Изоляция серверов

- Серверы цепочки связываются только через Cloudflare Mesh. Звено знает Mesh-адрес следующего звена и больше ничего; выход видит подключения только с Mesh-адреса предыдущего звена.
- Каждое звено шифруется отдельно (VLESS Encryption, ML-KEM-768 + X25519, режим `random`). Вход упаковывает поток слоями, поэтому промежуточный сервер не может прочитать трафик и не знает конечного адреса; Cloudflare видит случайные байты.
- Промежуточный сервер может подключаться только к следующему звену. Выход не пускает трафик в частные сети, в Mesh и на порт 25.

## Порты

Политика по умолчанию — drop. Разрешены только:

| Сервер | Открыто |
| --- | --- |
| вход | SSH (с ограничением частоты подключений на источник, опционально — список адресов), порт панели (опционально — список адресов), UDP-порт WDTT, порты включённых подключений 3x-ui |
| промежуточный, выход | ничего из Интернета; SSH и порт звена — только из Mesh |

Ответы ICMP, нужные для определения MTU, разрешены всегда; ping — по желанию. Правила живут в собственной таблице `inet wdtt_router` и не трогают правила других программ.

Перед изменением firewall агент запускает таймер systemd, который через 2 минуты вернёт прежние правила. Панель подтверждает изменение, только если смогла подключиться к серверу **новым** соединением. Таймер вызывает `nft` напрямую, поэтому откат сработает даже при повреждённом бинарном файле. При загрузке восстанавливаются только подтверждённые правила.

## WDTT

`wdtt-server` при каждом запуске добавляет свой MASQUERADE; агент удаляет его, а таблица `wdtt_router_wdtt` запрещает любую пересылку с `wdtt0` и на него. Трафик клиентов попадает только в Xray через TPROXY, а сами клиенты не могут подключаться к службам входного сервера. Внутренний порт WireGuard наружу закрыт.

## Панель

- Только HTTPS (TLS 1.2+), самоподписанный сертификат — сверяйте отпечаток.
- Пароли — Argon2id; сессия 12 часов в cookie `Secure`, `HttpOnly`, `SameSite=Strict`; изменяющие запросы требуют CSRF-токен; ограничение попыток входа.
- Строгий CSP, HSTS, запрет встраивания во фреймы.
- Токен Cloudflare, Mesh-токены, ключи звеньев, пароли WDTT и 3x-ui хранятся в SQLite, зашифрованные AES-256-GCM. Ключ `master.key` лежит рядом с базой (0600). Входные данные задач (например, пароль root нового сервера) удаляются после выполнения.
- Секреты показываются только по отдельному запросу; каждый просмотр пишется в журнал действий.
- Пароль root нового сервера используется один раз для установки SSH-ключа панели и не сохраняется. Отпечаток SSH сервера запоминается и проверяется при каждом подключении.
- Нельзя сохранить список адресов для SSH или панели, если ваш текущий адрес в него не входит.

## Загружаемые компоненты

Xray, установщик 3x-ui, исходный код WDTT и инструментарий Go для его сборки скачиваются по закреплённым версиям и проверяются по SHA-256. `cloudflare-warp` ставится из подписанного репозитория Cloudflare.

## Рекомендации

- Используйте отдельный аккаунт Cloudflare Zero Trust только для цепочки и токен с минимальными правами.
- Ограничьте доступ к панели своими адресами (Настройки) и к SSH входного сервера.
- После передачи паролей и токенов в переписке смените их.
