# Безопасность

## Изоляция серверов

- Серверы цепочки связываются только через Cloudflare Mesh. Звено знает Mesh-адрес следующего звена и больше ничего; выход видит подключения только с Mesh-адреса предыдущего звена.
- Каждое звено шифруется отдельно (VLESS Encryption, ML-KEM-768 + X25519, режим `random`). Вход упаковывает поток слоями, поэтому промежуточный сервер не может прочитать трафик и не знает конечного адреса; Cloudflare видит случайные байты.
- Промежуточный сервер может подключаться только к следующему звену. Выход не пускает трафик в частные сети, в Mesh и на порт 25.

## Порты

Политика по умолчанию — drop. Разрешены только:

| Сервер | Открыто |
| --- | --- |
| вход | SSH (с ограничением частоты подключений на источник, опционально — список адресов), порт панели (опционально — список адресов), UDP-порт WDTT, порты включённых подключений 3x-ui |
| промежуточный, выход | ничего из Интернета; SSH и порт звена — только из Mesh |

Ответы ICMP, нужные для определения MTU, разрешены всегда; ping — по желанию. Правила живут в собственной таблице `inet wdtt_router` и не трогают правила других программ.

Перед изменением firewall агент запускает таймер systemd, который через 2 минуты вернёт прежние правила. Панель подтверждает изменение, только если смогла подключиться к серверу **новым** соединением. Таймер вызывает `nft` напрямую, поэтому откат сработает даже при повреждённом бинарном файле. При загрузке восстанавливаются только подтверждённые правила.

## WDTT

Сервер WDTT встроен в панель ([подробнее](wdtt.md)). Он не трогает firewall и NAT; таблица `wdtt_router_wdtt` запрещает любую пересылку с `wdtt0` и на него, поэтому трафик клиентов попадает только в Xray через TPROXY, а сами клиенты не могут подключаться к службам входного сервера. Порта WireGuard нет: пакеты WireGuard передаются только внутри DTLS-сессий.

- На датаграммы без правильного ключа сервер не отвечает; новое соединение создаётся только после расшифровки ключом одного из паролей, попытки расшифровки ограничены по IP-адресу.
- Пароль в запросе конфигурации должен совпадать с ключом сессии. Ключ доступа привязан к одному устройству; отключение, истечение срока и удаление сразу закрывают его сессии.
- Служба работает с единственной возможностью `CAP_NET_ADMIN`, без новых привилегий, с файловой системой только для чтения (кроме своей папки данных) и фильтром системных вызовов.

## Панель

- Только HTTPS (TLS 1.2+), самоподписанный сертификат — сверяйте отпечаток.
- Пароли — Argon2id; сессия 12 часов в cookie `Secure`, `HttpOnly`, `SameSite=Strict`; изменяющие запросы требуют CSRF-токен; ограничение попыток входа.
- Строгий CSP, HSTS, запрет встраивания во фреймы.
- Токен Cloudflare, Mesh-токены, ключи звеньев, пароли WDTT и 3x-ui хранятся в SQLite, зашифрованные AES-256-GCM. Ключ `master.key` лежит рядом с базой (0600). Входные данные задач (например, пароль root нового сервера) удаляются после выполнения.
- Секреты показываются только по отдельному запросу; каждый просмотр пишется в журнал действий.
- Пароль root нового сервера используется один раз для установки SSH-ключа панели и не сохраняется. Отпечаток SSH сервера запоминается и проверяется при каждом подключении.
- Нельзя сохранить список адресов для SSH или панели, если ваш текущий адрес в него не входит.

## Загружаемые компоненты

Xray и установщик 3x-ui скачиваются по закреплённым версиям и проверяются по SHA-256. Сервер WDTT входит в бинарный файл панели. `cloudflare-warp` ставится из подписанного репозитория Cloudflare.

## Защита серверов

В разделе «Безопасность» для каждого сервера:

- **Вход по SSH только по ключу.** Панель пишет настройки в начало `/etc/ssh/sshd_config` (до `Include`, поэтому их не перекрывают файлы провайдера), проверяет `sshd -t` и затем фактическое значение `sshd -T`. Если у root нет ни одного ключа, режим не включится. Выключение возвращает настройки провайдера.
- **Свои SSH-ключи.** Хранятся в отмеченном блоке `authorized_keys` root; ключ панели и добавленные вручную ключи не трогаются.
- **Автоматические обновления безопасности** через `unattended-upgrades` (только security-обновления, без автоматической перезагрузки; о нужной перезагрузке сообщает панель и бот).
- **Замена SSH-ключа панели**: новый ключ добавляется и проверяется на каждом сервере, только потом старый удаляется. После замены скачайте новую резервную копию — в прежних старый ключ.

## Доступ к панели

Три режима: из любого адреса, только с указанных адресов, только через Cloudflare Mesh. В последнем порт панели закрыт для Интернета, открыть её можно с устройства с Cloudflare WARP вашей команды по Mesh-адресу сервера. Внутри Mesh панель доступна всегда (так к ней обращается и Telegram-бот). Режим «только Mesh» включается лишь из сессии, которая уже идёт через Mesh.

## Telegram-бот

Работает на выбранном сервере как служба без привилегий (`wdtt-router-bot`), не открывает портов. К панели обращается через Mesh с отдельным ключом, который даёт только чтение событий и сводки `/status` и привязку чатов; сертификат панели закреплён. Отвечает только чатам, привязанным одноразовым кодом из панели (10 минут, 5 попыток). `/status` не содержит адресов, ключей и паролей.

## Резервные копии и обновления

- Копия панели шифруется паролем, который задаёте вы (scrypt, AES-256-GCM); без него файл бесполезен. Восстановление: `wdtt-router restore`.
- Релизы подписаны ключом Ed25519 проекта (`release-signing.pub`). Установщик проверяет подпись `SHA256SUMS` через `openssl`, панель — встроенным ключом; сборка с несовпадающей подписью не ставится. Для подписи релизов в репозитории нужен секрет `RELEASE_SIGNING_KEY` (закрытый ключ PEM); без него сборка релиза останавливается.
- Архив диагностики не содержит файлов настроек, а значения, похожие на пароли, ключи и токены, в журналах скрыты.

## Рекомендации

- Используйте отдельный аккаунт Cloudflare Zero Trust только для цепочки и токен с минимальными правами.
- Ограничьте доступ к панели своими адресами (Настройки) и к SSH входного сервера.
- После передачи паролей и токенов в переписке смените их.
