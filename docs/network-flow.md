# Путь трафика

```text
PWDTT → WDTT на входном VPS → wdtt0 → выборочное правило/таблица
      → Cloudflare Mesh → выходной VPS → Internet

Необязательный режим:
wdtt0 → Xray TPROXY → VLESS внутри Mesh → 3x-ui на выходном VPS
      → прямой outbound Xray или приватный WARP outbound → Internet
```

Исходящий маршрут основного хоста входного VPS остаётся в его обычной таблице. Правило приоритета `10667` и таблица `51889` направляют только пакеты источника `10.66.66.0/24` в Mesh. На входе Mesh используется SNAT к Mesh IP, потому что Cloudflare принимает этот источник; на выходном VPS есть обратный маршрут к подсети WDTT через контейнерный мост и NAT в публичный интерфейс. Конкретные имена, адреса, таблица и приоритет хранятся в конфигурации узла.

При включении VLESS пакеты WDTT, пришедшие на `wdtt0`, попадают в `iptables mangle PREROUTING` и Xray TPROXY с отдельной mark/table `51888`. Локальные и приватные назначения исключены из перехвата. Xray посылает TCP и UDP по приватному Mesh адресу выходного узла. 3x-ui управляет выделенным входом, который не слушает публичный интерфейс. Выключение VLESS клиента удаляет только правила и службу, принадлежащие панели, и возвращает прямой Mesh маршрут.

Необязательный WARP регистрируется через 3x-ui и добавляет отдельный WireGuard outbound `wdtt-panel-warp`. Правило 3x-ui направляет в него только трафик приватного VLESS входа. Панель выбирает IPv4 адрес WARP endpoint для узла без рабочего IPv6, перезапускает Xray, проверяет загруженное правило и затем проверяет синтетический TCP/UDP поток с входного VPS. При выключении удаляются только созданные панелью outbound и правило.

В самопроверке используются отдельный сетевой namespace и проверка TCP/UDP через полный путь. Это подтверждает передачу пакетов на VPS; оно не заменяет подключение настоящего PWDTT клиента.
Обычная проверка `wdtt-panel selftest` также выполняет запрос с адреса `wdtt0`; он проходит прямой Mesh путь и может показать IP выходного VPS даже при включённом WARP. Для проверки именно прозрачного пути используйте `wdtt-panel node probe-vless-client-json`.

Cloudflare Mesh требует маршрутов `0.0.0.0/1` и `128.0.0.0/1` к выходному узлу и `10.66.66.0/24` к входному в отдельном тестовом аккаунте. Применять эти маршруты в аккаунте с уже работающими маршрутами нельзя без проверки конфликтов.
