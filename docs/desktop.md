# Приложение для Windows

`wdtt-router-windows-amd64.exe` (или `-arm64.exe`) из релиза — окно с панелью и значок в трее. Панель по-прежнему работает на сервере круглосуточно: статистика, проверки цепочки, задачи и Telegram-бот не зависят от того, включён ли компьютер. Приложение только подключается к ней.

## Как это устроено

- У приложения свой SSH-ключ ed25519. Закрытая часть хранится в `%APPDATA%\WDTT Router\app_key`, зашифрованная DPAPI для учётной записи Windows: файл, скопированный на другой компьютер или под другого пользователя, не расшифруется.
- Приложение входит на сервер панели по SSH (root, по ключу) и выполняет `wdtt-router desktop-login`: команда создаёт обычную сессию панели на 12 часов и сообщает порт и отпечаток сертификата. Пароль панели не нужен — тот, кто может войти root по SSH, и так управляет сервером. Сессия продлевается сама; в журнале аудита это `login.desktop`, а первый вход с нового компьютера попадает в события (и в Telegram).
- Панель открывается через SSH-туннель к `127.0.0.1:порт_панели` на сервере. Сертификат проверяется по отпечатку, полученному по SSH, поэтому предупреждений браузера нет. Ключ SSH сервера запоминается при первом подключении; если он изменится, приложение откажется подключаться.
- Окно показывает страницы с локального адреса `127.0.0.1:случайный_порт`. Ответы получает только окно приложения: нужен секрет, который приложение передаёт окну при запуске, и точное имя хоста.
- Значок в трее показывает состояние (то же, что `/status` в Telegram): зелёный — всё работает, красный — сервер недоступен, цепочка или WDTT не работают, серый — нет подключения. Новые события панели приходят уведомлениями Windows. Закрытие окна убирает его в трей; «Выход» — в меню значка. Там же «Запускать вместе с Windows».

## Первый запуск

1. Укажите IP сервера и пароль root (его присылает хостинг). Пароль нужен один раз: приложение добавит в `~/.ssh/authorized_keys` свой ключ с комментарием `wdtt-router-app@ИМЯ_КОМПЬЮТЕРА`, проверит вход по нему и забудет пароль. Можно обойтись без пароля: добавьте открытый ключ приложения (внизу стартового экрана) на сервер заранее, например в панели хостинга.
2. Приложение посмотрит, что установлено на сервере:
   - панели нет (Debian или Ubuntu) — предложит установить: загрузит `install.sh` из последнего релиза, установщик проверит подпись, и панель запустится. Пароль панели показывается один раз — он нужен только для входа из браузера;
   - панель старая — предложит обновить (`install.sh update`, с откатом при ошибке);
   - на сервере только агент — подскажет, что нужно указать сервер, на котором установлена панель.
3. «Открыть панель» — дальше всё как в браузере. Пункт «Серверы приложения» в меню пользователя возвращает к списку серверов.

## Закрыть порт панели

Настройки → Доступ к веб-панели → «Только из приложения или через Mesh». Порт панели закрывается для Интернета; приложение продолжает работать, потому что подключается по SSH. Включить режим можно из приложения или из сессии через Mesh — так вы не потеряете доступ.

Публичный SSH сервера панели приложению нужен. Панель не даст закрыть его из приложения, если приложение подключено к серверу по публичному адресу (а не по адресу Mesh).

## Если что-то не так

- **«Сервер больше не принимает ключ приложения»** — ключ удалили из `authorized_keys` (или сервер переустановлен). Добавьте сервер снова, указав пароль root.
- **«Ключ SSH сервера изменился»** — если сервер переустанавливали, уберите его из списка и добавьте снова. Если нет — не подключайтесь: соединение может перехватываться.
- **Нет WebView2** — на Windows 10 без обновлений приложение предложит установить Microsoft Edge WebView2 Runtime.
- **SmartScreen** при первом запуске предупреждает о неизвестном издателе (файл не подписан сертификатом Authenticode). Проверить файл можно по `SHA256SUMS` релиза, который подписан ключом проекта (см. [security.md](security.md)).
- Журнал приложения: `%APPDATA%\WDTT Router\app.log`.
- Убрать доступ приложения с сервера: удалите строку `wdtt-router-app@…` из `/root/.ssh/authorized_keys`.
