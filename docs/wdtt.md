# Сервер WDTT

Сервер WDTT встроен в `wdtt-router` (`wdtt-router wdtt-server`, пакет `internal/wdtt`). Это собственная реализация, совместимая со стандартными клиентами WDTT: тот же протокол, тот же ответ на запрос конфигурации и та же ссылка `wdtt://`. Код исходного сервера не используется; исходный проект прекратил развитие.

## Протокол

Клиент держит несколько параллельных сессий, каждая через свою выделенную на TURN-сервере VK позицию (allocation). Сервер видит обычные UDP-датаграммы с адресов TURN-ретрансляторов.

| Уровень | Что передаётся |
| --- | --- |
| UDP | на порт DTLS (по умолчанию 56000) |
| Маскировка | каждая датаграмма — RTP v2 с флагом padding: заголовок 12 байт, полезная нагрузка, зашифрованная ChaCha20-Poly1305 (заголовок — дополнительные данные), 1..N байт выравнивания. Тип полезной нагрузки 111 (аудио) или 96 (видео); сервер отвечает тем же типом, что прислал клиент. Ключ — HKDF-SHA256 от пароля (соль `WDTT-WRAP-v1`, info `rtp-obfs/chacha20poly1305`), nonce — SSRC, номер пакета и метка времени из заголовка |
| DTLS 1.2 | ECDHE-ECDSA-AES128-GCM-SHA256, обязательный Extended Master Secret, Connection ID |
| Первое сообщение | `GETCONF:<локальный порт>\|<id устройства>\|<пароль>` → конфигурация WireGuard или `DENIED:wrong_password`, `DENIED:expired`, `DENIED:deactivated`, `DENIED:device_mismatch`, `NOCONF`. `READY` → `READY_OK` |
| Дальше | пакеты WireGuard; один байт `0xFF` — keepalive клиента (раз в 15 с) |

Ссылка для клиента: `wdtt://АДРЕС:ПОРТ_DTLS:ПОРТ_WG:9000:ПАРОЛЬ:ХЕШИ_ЗВОНКОВ`. Порт WG нужен только для совместимости формата: у встроенного сервера нет отдельного порта WireGuard.

## Чем отличается от исходного сервера

| | Исходный сервер | Встроенный |
| --- | --- | --- |
| Путь пакета к WireGuard | DTLS → UDP-сокет на 127.0.0.1 → WireGuard (лишний проход через ядро, своя UDP-связка на каждую сессию) | DTLS → WireGuard напрямую (собственный `conn.Bind`), порта WireGuard нет вовсе |
| Приём UDP | один сокет | несколько сокетов `SO_REUSEPORT` по числу ядер (до 8) |
| Чужие датаграммы | создают соединение и запускают DTLS | отбрасываются до DTLS: новое соединение создаётся только датаграммой, расшифрованной одним из ключей и содержащей начало рукопожатия; ограничение попыток расшифровки на IP-адрес |
| Пароль сессии | сессия с любым ключом может запросить конфигурацию по любому паролю | пароль в `GETCONF` должен совпадать с ключом, которым зашифрована сессия |
| Отказ в доступе | после `DENIED` сессия продолжает работать | сессия закрывается |
| Обрыв одной сессии клиента | ответы WireGuard уходят в закрытую сессию, пока клиент не пришлёт следующий пакет | ответы уходят через другую живую сессию того же клиента |
| Перезапуск сервера | клиенты не узнают о нём и ждут до 30 минут (таймаут чтения клиента) | при остановке всем сессиям отправляется close_notify; после сбоя на первый же пакет старой сессии сервер отвечает сбросом — клиент переподключается за секунды |
| Отключение или удаление пароля | — | сессии этого пароля закрываются сразу, устройство отключается от WireGuard |
| Пароли | пароль владельца и до 10 временных через Telegram-бота | пароль владельца и до 200 ключей доступа в панели: срок, отключение, отвязка устройства, трафик, ссылка и QR-код |
| Изменение паролей | перезапуск | перечитывание конфигурации (SIGHUP) без разрыва подключённых клиентов |
| NAT | добавляет MASQUERADE и правила FORWARD при каждом запуске | ничего не меняет в firewall; трафик клиентов уходит только в цепочку через TPROXY |
| Привилегии | root | служба с одной возможностью `CAP_NET_ADMIN`, файловая система только для чтения, кроме своей папки данных |
| Установка | загрузка Go (~75 МБ) и сборка из исходников на сервере (~2 минуты) | часть бинарного файла панели, запуск за секунды |

Замер на тестовых серверах (вход и выход по 1 vCPU, цепочка через Cloudflare Mesh, тот же тестовый клиент): исходный сервер — около 22 Мбит/с, встроенный — около 29,5 Мбит/с; с клиентом на отдельной машине — около 40 Мбит/с. На однопроцессорном сервере предел задают шифрование и DTLS.

## Ключи доступа

- **Пароль владельца** не привязывается к устройству; им можно подключать сколько угодно своих устройств. Его можно сменить на случайный или задать свой — например, пароль прежнего сервера, чтобы его клиентам ничего не менять.
- **Ключ доступа** — отдельный пароль, который привязывается к первому подключившемуся устройству. Срок действия, отключение, отвязка устройства и удаление применяются сразу и не задевают других клиентов.
- Адреса клиентов — 10.66.66.2–10.66.66.250. Устройство сохраняет свой адрес и ключи WireGuard между подключениями. Устройства пароля владельца, не подключавшиеся 180 дней, удаляются.

## Файлы

| Путь | Содержимое |
| --- | --- |
| `/etc/wdtt-router/wdtt.json` (0600) | порт, DNS, пароль владельца, ключи доступа — пишет агент |
| `/var/lib/wdtt-router/wdtt/state.json` (0600) | ключи сервера WireGuard, устройства, привязки и трафик ключей |
| `/run/wdtt-router/wdtt-status.json` | состояние для панели: сессии, устройства, трафик, отказы (обновляется каждые 5 с) |

При первом запуске сервер переносит ключ WireGuard и устройства исходного сервера из `wg-keys.dat` и `passwords.json` той же папки, поэтому клиенты сохраняют свои адреса.

## Диагностика

```bash
systemctl status wdtt-router-wdtt
journalctl -u wdtt-router-wdtt -f
cat /run/wdtt-router/wdtt-status.json
systemctl reload wdtt-router-wdtt      # перечитать пароли без разрыва клиентов
```
