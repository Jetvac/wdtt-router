# Изменения

## 1.3.0 — 2026-11-14

- Два сервера WDTT вместо одного: для стандартного приложения WDTT и для нашего клиента TurnVK. Каждый включается отдельно, работает на своём UDP-порту (по умолчанию 56000 и 56010), со своим паролем владельца, ключами и устройствами; в панели они везде подписаны. Протокол пока одинаковый — сервер для TurnVK нужен, чтобы менять протокол для нашего клиента, не задевая стандартных клиентов. Существующий сервер и все его ключи остаются как были: это сервер для стандартного клиента.
- Ключ доступа больше не ограничен одним устройством: у каждого ключа своё число устройств — от 1 до 249 или без ограничения. Новые ключи по умолчанию без ограничения; у ключей, выданных раньше, остаётся одно устройство (число можно поменять). Когда все места заняты, новое устройство получает тот же отказ, что и раньше («ключ используется на другом устройстве»).
- Устройства каждого ключа видны в его строке: адрес в туннеле, сессии, трафик, когда было в сети и когда привязано. Отдельное устройство можно отвязать, не трогая остальные; «Отвязать все устройства» — как раньше.
- Новая вкладка «Устройства» на странице WDTT: все устройства обоих серверов (и пароля владельца) в одном списке с поиском и фильтром «в сети».
- В резервную копию входят данные обоих серверов WDTT.
- 3x-ui: подписки можно открыть для Интернета — переключатель «Подписки из Интернета» в карточке 3x-ui. Панель откроет порт сервера подписок (2096 по умолчанию) и пропишет в 3x-ui публичный адрес, чтобы ссылки подписок вели на сервер, а не на 127.0.0.1. Свой адрес подписок, заданный в 3x-ui (например, домен за обратным прокси), панель не трогает. По умолчанию подписки, как и раньше, доступны только через SSH-туннель.
- 3x-ui: панель предупреждает о подключении, которое примет клиента, но не пропустит трафик — VLESS с транспортом XHTTP, WS или gRPC и Flow `xtls-rprx-vision` у клиентов (Vision работает только с TCP). Клиент в таком случае подключается и даже получает DNS, но сайты не открываются.

## 1.2.5 — 2026-11-09

Полная проверка на чистых серверах: установка, приложение, Mesh, цепочка, WDTT, 3x-ui, режим «только из приложения или через Mesh», перезагрузки, отключение и удаление серверов. Найденное исправлено:

- Исправлено: «Отключить от Mesh» и «Удалить» для сервера с закрытым публичным SSH не работали. Первое требовало сначала вручную открыть SSH, второе выполнялось через сам Mesh, обрывалось на середине (`• leaving Cloudflare Mesh`) и оставляло на сервере часть файлов. Теперь панель сама открывает публичный SSH, проверяет, что он отвечает, и только потом выводит сервер из Mesh — уже по публичному адресу. При повторном подключении к Mesh открытый так SSH снова закрывается, когда Mesh заработает.
- Агент на сервере доводит начатое до конца, даже если связь с панелью оборвалась посреди шага.
- Удаление сервера убирает с него и сам `wdtt-router`.
- Добавить сервер можно без пароля, если на нём уже есть ключ панели — например, когда вход по паролю отключён. Команда для добавления ключа — в окне «Добавить сервер», пароль root теперь необязателен. То же в приложении для Windows: команда с ключом приложения показана прямо в запросе пароля.
- В разделе Cloudflare Mesh можно удалить Mesh-узлы, оставшиеся от переустановленных серверов (каждый сброс сервера оставлял в аккаунте лишний узел). Удалить можно только узел, который панель не использует и который сейчас не подключён, и только после подтверждения.
- После перезапуска Xray агент проверяет, что тот действительно принимает соединения (SOCKS на входе, порт звена на остальных серверах), а не только что служба числится запущенной. Если нет — в журнале задачи сразу видно, кто занял порт и что написал Xray. Та же подсказка добавляется к ошибке проверки цепочки `connection refused`.
- Если сервер с закрытым публичным SSH недоступен, ошибка называет причину — Mesh, а не таймаут публичного адреса.

## 1.2.4 — 2026-11-09

- Исправлено: сервер панели не подключался к Mesh (`NO_PUBKEY 6E2DD2174FA1C3BA … is not signed`). Агент на сервере панели наследовал `UMask=0077` службы панели, и ключ репозитория Cloudflare получал права `0600` — apt проверяет подписи от пользователя `_apt` и не мог его прочитать. Теперь ключ всегда `0644`, а агент работает с umask `022`, как на остальных серверах (файлы с секретами по-прежнему `0600`).
- Если установить Cloudflare One client не удалось, агент убирает репозиторий из источников apt, чтобы не ломать остальные обновления сервера.

## 1.2.3 — 2026-11-09

- Загрузка релиза больше не зависит от прямых ссылок GitHub: когда `github.com/…/releases/download/…` отвечает 504 (так бывает часами), панель, установщик и приложение загружают те же файлы через API GitHub. Безопасность не меняется — всё сверяется с подписанным `SHA256SUMS`.
- Приложение для Windows загружает установщик само, проверяет подпись релиза и передаёт его на сервер по SSH.

## 1.2.2 — 2026-11-09

- Исправлено: при подключении нового сервера к Mesh панель закрывала его публичный SSH в том же шаге, когда Mesh-узел ещё не успел заработать, — проверка доступа не проходила, и подключение откатывалось (`после изменения firewall панель не смогла подключиться заново`). Теперь публичный SSH закрывается только после того, как панель действительно вошла на сервер через Mesh (ожидание до 90 с). Если Mesh-связь не появилась, сервер остаётся доступным, а панель закроет SSH при следующем применении настроек.
- Если сервер панели ещё не в Mesh, при добавлении другого сервера панель сначала подключает к Mesh себя.

## 1.2.1 — 2026-11-09

- Исправлено: `install.sh install` в 1.2.0 не работал на чистом сервере — переменная `VERSION` из `/etc/os-release` подменяла версию релиза, и загрузка падала с `curl: (3) URL rejected`. Обновление (`install.sh update`) ошибка не затрагивала.

- Приложение для Windows (`wdtt-router-windows-amd64.exe`, `-arm64.exe`, со своим значком): окно с панелью и значок в трее с состоянием серверов и уведомлениями о событиях. Подключается к панели через SSH-туннель со своим ключом (закрытая часть зашифрована DPAPI) — без пароля панели и предупреждений о сертификате; сертификат проверяется по отпечатку, полученному по SSH. На чистый сервер с Debian или Ubuntu само устанавливает панель (пароль root нужен один раз и не сохраняется), устаревшую панель обновляет. См. [docs/desktop.md](docs/desktop.md).
- `wdtt-router desktop-login` — сессия панели для приложения (только для root на сервере); первый вход с нового компьютера попадает в события.
- Режим «только через Mesh» теперь «только из приложения или через Mesh»: включается и из приложения. Панель не даст закрыть из приложения публичный SSH сервера, через который приложение подключено.
- `GET /api/summary` — краткое состояние для значка в трее.

## 1.2.0 — 2026-11-08

Панель:

- Защита серверов (раздел «Безопасность»): вход по SSH только по ключу (настройки пишутся в начало `sshd_config`, проверяются `sshd -t` и фактическим `sshd -T`; без ключа у root включить нельзя), автоматические обновления безопасности, свои SSH-ключи администратора. Статус показывает, что действует на самом деле, и нужна ли перезагрузка.
- Замена SSH-ключа панели на всех серверах: новый ключ добавляется и проверяется везде, только потом старый удаляется. `wdtt-router ssh-key` выводит открытый ключ панели.
- Telegram-бот: уведомления (сервер недоступен, цепочка не работает, WDTT остановлен, вход с нового адреса, подбор пароля, нужна перезагрузка, ошибки задач, новая версия) и команда `/status`. Работает на выбранном сервере, портов не открывает, к панели обращается через Mesh со своим ключом и закреплённым сертификатом; адрес Telegram ищет через DNS-over-HTTPS. Чаты привязываются одноразовым кодом.
- Зашифрованные резервные копии из панели (пароль копии, scrypt + AES-256-GCM) и `wdtt-router restore` на этом или новом сервере.
- Подписанные релизы: `SHA256SUMS` подписан ключом Ed25519; установщик и панель отказываются ставить сборку с чужой подписью. Обновление и откат из панели, баннер о новой версии.
- Доступ к панели только через Cloudflare Mesh (порт закрыт для Интернета); включается только из сессии через Mesh. Внутри Mesh панель доступна всегда.
- Обзор: графики нагрузки, памяти, трафика, сессий WDTT и задержки цепочки за сутки и неделю; лента событий.
- Отдельная страница WDTT: счётчики, настройки, ключи с поиском; новый ключ сразу показывает ссылку и QR-код.
- Тёмная тема, архив диагностики со всех серверов (секреты скрыты).

WDTT:

- WDTT: после перезапуска или сбоя сервера туннель восстанавливается за секунды, а не через ~16 с. Сервер сам начинает рукопожатие WireGuard с устройством, которое продолжает слать данные со старыми ключами; если ответ потерялся в ещё не переподключённой сессии клиента, повторяет через самую новую сессию. Работает для любых клиентов WDTT.
- WDTT: после сбоя (без штатной остановки) сервер сразу отправляет сброс всем сессиям, которые были у него до сбоя (список хранится в `/run`), — клиенты, которые понимают сброс, переподключаются, не дожидаясь своего трафика.
- WDTT: MTU туннеля задаётся в панели (1200–1340, по умолчанию 1280) и меняется без разрыва клиентов; клиенты получают новое значение при переподключении.
- WDTT: служба перезапускается через 1 с после сбоя (было 3 с); лимит попыток расшифровки с одного IP поднят до 256 в секунду — через один IP TURN-сервера VK идут многие клиенты.
- `kill -USR1` процессу сервера WDTT записывает 20-секундный профиль CPU в `/run/wdtt-router/wdtt-cpu.pprof`.

## 1.1.0 — 2026-11-08

- Собственный сервер WDTT вместо исходного (проект прекратил развитие). Совместим со стандартными клиентами: тот же протокол, ответ `GETCONF` и ссылка `wdtt://`. Устройства и ключ WireGuard прежнего сервера переносятся автоматически.
  - WireGuard получает пакеты прямо из DTLS-сессий, без UDP-сокета на 127.0.0.1; приём на нескольких сокетах `SO_REUSEPORT`. На тестовой цепочке скорость выросла примерно с 22 до 29,5 Мбит/с.
  - Клиенты переподключаются за секунды после перезапуска или сбоя сервера (раньше — до 30 минут).
  - При обрыве одной сессии ответы идут через другие сессии того же клиента.
  - Чужие датаграммы отбрасываются до DTLS; пароль в запросе конфигурации должен совпадать с ключом сессии; после отказа сессия закрывается.
  - Служба с одной возможностью `CAP_NET_ADMIN`, без изменения firewall и NAT. Не нужно скачивать Go и собирать сервер на сервере.
- Ключи доступа WDTT в панели: отдельный пароль на устройство с привязкой, сроком, отключением, отвязкой, статистикой трафика, ссылкой `wdtt://` и QR-кодом. Изменения применяются без разрыва остальных клиентов. Пароль владельца можно задать вручную (например, пароль прежнего сервера).
- Сетевые настройки ядра на всех серверах: BBR, fq, увеличенные буферы сокетов.
- Исправлено: задача обслуживания могла восстановить старые правила firewall, если применение настроек завершалось во время её ожидания.

## 1.0.0 — 2026-11-08

Полная переработка.

- Связь между серверами только через Cloudflare Mesh (нативный `cloudflare-warp`, профиль Include с одним диапазоном Mesh). Цепочка любой длины: вход → промежуточные → выход.
- Луковичное шифрование звеньев (VLESS Encryption, ML-KEM-768 + X25519); промежуточные серверы не видят трафик и конечные адреса.
- Декларативное состояние серверов и идемпотентный агент; единая очередь задач с объединением повторных запросов.
- Firewall nftables с политикой drop на каждом сервере, SSH промежуточных и выходных серверов только через Mesh, защита SSH от перебора по источнику, откат правил без участия бинарного файла.
- WDTT и 3x-ui независимы и могут включаться и выключаться в любом порядке. Kill switch для клиентов WDTT, автоматическое открытие портов 3x-ui.
- WDTT собирался из закреплённого коммита исходного проекта (в 1.1.0 заменён собственным сервером).
- Новый интерфейс на React + Ant Design, адаптивный.
- Восстановление после перезагрузки и после сброса правил маршрутизации systemd-networkd.
- SQLite без CGO, сборка под amd64/arm64.
